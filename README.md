# openflux-install

Интерактивный установщик серверной ноды [OpenFlux](https://github.com/p1neappleXpress/OpenFlux) для Ubuntu/Debian с systemd. Помогает развернуть выходной узел в режиме `l4`, добавлять устройства и выдавать им ссылки подключения без ручного редактирования конфигурации.

Это отдельный вспомогательный проект, не официальный установщик команды OpenFlux. Само ядро скачивается из официальных GitHub Releases и проверяется по `SHA256SUMS`.

## Возможности

- Установка последнего стабильного серверного релиза `node-v*` для amd64/arm64.
- Яндекс Документы, Телемост, Яндекс Доска, Mail.ru Документы, Cups.online.
- Подсказки по созданию ссылок; автоматическое создание Cups-комнат штатным мастером ядра.
- Отдельные ключи, конфигурации и systemd-сервисы для каждого устройства.
- Проверка повторных имён, ссылок и зарезервированных TCP-портов.
- Опциональный резерв `direct`, настройка активного UFW/firewalld.
- Нумерованный список клиентов с указанием сервиса и состояния; удаление клиента.
- Проверка обновлений и ручное обновление ядра с возвратом старого бинарника при сбое запуска сервисов.
- Справка по iOS/iPadOS, Android, macOS, Windows и Linux.
- Возврат в главное меню после операций, цветной вывод и ссылки для поддерживающих терминалов.

## Требования

Ubuntu/Debian с Python 3.9 или новее, systemd, root или sudo, исходящий интернет. Для Телемоста нужен исходящий UDP/WebRTC. Установка использует `apt-get`. Рекомендуется начинать проверку на отдельном VPS.

## Быстрый путь: свежий VPS → телефон

1. Скачайте один файл `openflux-setup.sh` из ветки **experimental** этого репозитория. Это экспериментальная ветка; она не устанавливается на действующий VPS автоматически.
2. Передайте файл на VPS и запустите под root командами ниже.
3. Выберите **14**, чтобы проверить среду до изменений, затем **1** для первой установки.
4. Введите уникальное имя устройства, выберите транспорт и подготовьте ссылку по подсказке. Если добавляете `direct`, разрешите показанный TCP-порт также в панели провайдера.
5. Импортируйте выданную ссылку в приложении телефона и разрешите VPN. Ссылку не публикуйте.
6. Откройте сайт и проверьте внешний IP. При сбое используйте **8 — Диагностика**, затем прочитайте раздел типичных ошибок.

## Запуск

Скачайте `openflux-setup.sh` из этого репозитория на свой компьютер. Передайте на VPS, подставив свои значения:

```bash
scp -i /path/to/ssh-key -P 22 openflux-setup.sh root@SERVER_IP:/root/
ssh -i /path/to/ssh-key -p 22 root@SERVER_IP
bash /root/openflux-setup.sh
```

Если вошли обычным пользователем, выполните `sudo bash /путь/openflux-setup.sh`.

### Главное меню

| Пункт | Действие |
|---|---|
| 1 | Первая настройка сервера и первый клиент |
| 2 | Добавление клиента |
| 3 | Удаление клиента с выбором номера |
| 4 | Список клиентов и сервисов |
| 5 | Установка и настройка клиентских приложений |
| 6 | Проверка новой версии серверного ядра |
| 7 | Обновление серверного ядра |
| 8 | Диагностика выбранного клиента |
| 9 | Повторно показать ссылку подключения и QR |
| 10 | Создать шифрованную резервную копию |
| 11 | Восстановить профили из архива |
| 12 | Вернуть предыдущее ядро |
| 13 | Обновить сам установщик |
| 14 | Проверить сервер до изменений |
| 15 | Показать журнал операций |
| 0 | Выход |

После операции нажмите Enter для возврата в меню. При добавлении задайте уникальное имя устройства, выберите сервис и вставьте ссылку по подсказке. Укажите, нужен ли резервный `direct`. На вопрос создания профиля Enter означает «да».

Скрипт выдаст строку `openflux://…`. В приложении устройства выберите «Ключ или ссылка», импортируйте строку и подключитесь. Для каждого одновременно работающего устройства используйте отдельный канал и отдельный документ/встречу/набор комнат.

| Сервис | Что подготовить |

| Яндекс Документы | На [docs.yandex.ru](https://docs.yandex.ru/) создайте пустой документ, включите редактирование по ссылке. Скопируйте адрес редактора `/edit/d/…` |

| Яндекс Доска | На [boards.yandex.ru](https://boards.yandex.ru/) создайте доску, разрешите редактирование по ссылке. Сохраните параметр `?hash=…` в приглашении |
| Mail.ru Документы | В [Облаке Mail.ru](https://cloud.mail.ru/) создайте документ, настройте общий доступ с редактированием. Нужна ссылка `/public/…/…` |
| Cups.online | Выберите автосоздание комнат в скрипте либо вставьте ссылки `https://interview.cups.online/live-coding/?room=UUID` через пробел/готовый список OpenFlux |

При ограничении создания Cups-комнат (403/429) не повторяйте запросы многократно. Не используйте комнаты реальных собеседований.

## Порты и безопасность

Без `direct` новые входящие порты не требуются: нода сама подключается к стороннему сервису. Исходящие соединения должны быть разрешены.

Для `direct` выбирается свободный TCP-порт с учётом остановленных профилей. Он открывается в активном UFW/firewalld. Правило в сетевом экране провайдера VPS нужно добавить самостоятельно. При обнаружении пользовательских nftables/iptables-правил скрипт не изменяет их автоматически. SSH-правила не меняются.

Ссылка `openflux://…` содержит секрет. Не публикуйте её, QR-коды, SSH-ключи, cookies и серверные конфигурации. Скрипт хранит ключи и ссылки в `/etc/openflux-node/ИМЯ/` с ограниченными правами.

Удаление по номеру выполняется без повторного подтверждения: перед выбором убедитесь в имени. Скрипт проверяет сервисы и пути конфигурации; при удалении останавливает соответствующие сервисы и убирает файлы профиля. Правило firewall удаляется только при наличии записанных метаданных; внешние правила в панели провайдера удаляются отдельно.

## Диагностика

```bash
systemctl status openflux-managed@CLIENT_NAME --no-pager
journalctl -u openflux-managed@CLIENT_NAME -n 60 --no-pager -o cat
systemctl restart openflux-managed@CLIENT_NAME
```

Основные пути:

- `/opt/openflux-node/bin/` — версии ядра и ссылка на активный бинарник.
- `/etc/openflux-node/CLIENT_NAME/` — конфигурация, ключ, ссылка импорта.
- `/var/lib/openflux-node/CLIENT_NAME/` — cookies/состояние.
- `openflux-managed@CLIENT_NAME.service` — сервис клиента.

## Обновления

Пункты 6 и 7 ищут самый новый стабильный `node-v*` среди последних 100 релизов официального репозитория. Установка и обновление прекращаются при ошибке API, отсутствии сборки или неверной контрольной сумме. Уже установленное ядро первая настройка не заменяет; используйте пункт 7.

Перед обновлением скрипт требует шифрованную резервную копию профилей. Обновление перезапускает активные каналы стандартных шаблонов с ограниченным ожиданием. Если сервисы не стартуют или операция прервана, возвращается прежняя ссылка на бинарник и предпринимается ограниченная по времени попытка запуска прежних каналов. При её неудаче проверьте журнал; восстановление связи не гарантируется. Это проверка процессов, а не сквозной связи: после обновления проверьте сайты и внешний IP на устройствах. Клиентские приложения обновляются отдельно. Фонового автообновления нет.

## Ссылка и QR-код

Пункт **9** повторно показывает сохранённую ссылку выбранного клиента без смены ключа. По желанию QR-код генерируется локально утилитой `qrencode`; при её отсутствии скрипт предлагает установить пакет ОС. Внешние сайты-генераторы не используются. Для старых профилей без `client-link.txt` скрипт сообщает об отсутствии ссылки и не меняет профиль.

## Резервные копии и восстановление

Пункт **10** создаёт зашифрованный архив конфигураций, ключей и cookies. Введите новый абсолютный путь файла и дважды пароль длиной не менее 12 символов. Пароль не сохраняется и не передаётся через аргументы процесса. Скопируйте полученный файл вне VPS и храните пароль отдельно.

Формат архива: AES-256-CBC с PBKDF2 (300000 итераций) через OpenSSL и отдельная проверка HMAC-SHA256 до расшифровки. Это собственный формат установщика, не ZIP. Потерянный пароль восстановить нельзя. Лимит исходных данных профилей — 256 МБ, шифрованного файла — 512 МБ.

Пункт **11** принимает этот архив на уже подготовленном сервере с установленным ядром и пользователем `openflux-node`. На свежем VPS сначала выполните первую настройку; создание первого клиента можно отменить в запросе подтверждения. Затем восстановите архив. Пароль и целостность, пути, имена, ключи, конфликты портов и поддержка транспортов проверяются до записи профилей. Символические ссылки и спецфайлы не принимаются.

Существующие профили не перезаписываются. При конфликте остановитесь и используйте другой сервер либо заранее сохраните и удалите конфликтующий профиль. После восстановления каналы остаются остановленными; скрипт отдельно предлагает запуск и автозапуск. Исходные индивидуальные systemd-правки не восстанавливаются: используются стандартные сервисы установщика. Бинарник ядра в архив не входит; сохраняется информация о его версии. Правила firewall автоматически не импортируются — разрешите нужные direct-порты вручную, включая панель провайдера.

При ошибке восстановления созданные им профили убираются; чужие профили не затрагиваются. Восстановление не решает несовместимость клиентского ядра и не гарантирует отсутствие новой капчи после смены IP.

## Самообновление и откат

- **12:** возврат сохранённого предыдущего ядра после успешного обновления, с предварительной резервной копией и проверкой запуска сервисов.
- **13:** обновление только установщика из `Dgeliko/openflux-install`, ветка `experimental`. Загрузка привязана к полученному SHA коммита, затем проверяются тип файла и синтаксис Bash. Перед заменой сохраняется соседний файл `.previous.ДАТА`. Замена выполняется атомарно. После неё выйдите через 0 и запустите установщик заново.
- Приватный репозиторий без доступа вернёт понятную ошибку; текущий скрипт останется на месте. При необходимости заранее задайте `GH_TOKEN` с правом чтения репозитория. Скрипт не запрашивает и не сохраняет токен. Не вписывайте его в сам файл, команду запуска или Git-коммиты.
- Для ручного возврата установщика скопируйте нужный `.previous.ДАТА` на место рабочего файла после проверки пути. Пункт 12 возвращает **ядро**, а не файл установщика.

## Типичные ошибки

| Симптом | Что делать |
|---|---|
| `active`, но сайты не открываются | Пункт 8 показывает только доступные серверу признаки. Проверьте IP и сайты на устройстве: процесс не равен рабочему туннелю |
| `captcha required` | Проверка нужна на указанной стороне — клиенте или VPS. Если приложение не показывает окно, проверьте поддержку в его сборке |
| `classic-mode frames`, `Session peers only`, различающийся KDF | Проверьте совместимость клиента/ядра и импорт полного профиля. Не меняйте ключ наугад |
| `STRIPE gave up`, зависает видео | Есть потери/недоставленные фрагменты. Сравните Wi-Fi и мобильную сеть и активный транспорт; увеличение RAM само по себе не исправляет маршрут |
| Ошибка GitHub/API/404 | Проверьте сеть и доступ к приватному репозиторию. При обновлении HTML не будет исполнен вместо shell |
| Восстановление: имя или порт занят | Архив не применяется. Устраните конфликт отдельно; автоматической перезаписи нет |
| Зависание остановки | Установщик ждёт ограниченное время, затем завершает только выбранный сервис. При неудаче проверьте journalctl |

Журнал операций — `/var/log/openflux-install/operations.log`, права `600`, пункт **15**. В него записываются только идентификаторы действия/клиента и результат, без ввода пользователя, ключей, ссылок и cookies. Не путайте его с журналом самого OpenFlux: системный журнал может содержать ссылки транспорта. Автоматическая ротация журнала операций не настроена.

## Ограничения и статус проверки

- Телемост и другие сторонние транспорты зависят от доступности и изменений сервисов.
- Яндекс может требовать капчу на клиенте и VPS; её интерфейс зависит от сборки приложения. Установщик капчу не решает.
- Для одиночного транспорта без `direct` используется совместимый режим с ключом. С `direct` требуется Session-совместимый клиент.
- В некоторых сборках OpenFluxDesktop Телемост недоступен в режиме «Весь трафик»: используйте локальный прокси.
- Проверены синтаксис, форматы ссылок, генерация профилей и отдельные операции на VPS. Сценарий выбора последней версии проверен на тестовых данных. Реальные туннели Доски, Mail.ru и Cups.online, а также полный цикл обновления с откатом не проверены.
- `active` и «Подключено» не гарантируют передачу трафика. Проверяйте сайты, внешний IP и активный транспорт, особенно с резервным `direct`.

## Разработка

```bash
bash -n openflux-setup.sh
python3 -m unittest discover -s tests -v
```

Изменения системных сервисов требуют проверки на тестовом VPS. Не включайте реальные секреты в коммиты.

Проверки в `tests/` выполняются на временных данных и имитациях системных команд. Это не тестирование на чистых Ubuntu/Debian и не система выпусков. Новый установщик, обновление с откатом и перенос профилей нужно отдельно проверять на тестовом VPS перед распространением.
